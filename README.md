## 📘 نظرة عامة على المشروع

تم تصميم منصة **EduSmart (إديوسمارت)** لتكون نظام إدارة تعلم (LMS) وإدارة أكاديمية حديث، يخدم الطلاب، المعلمين، والمشرفين (Admins / Super Admins)، وتوفر تجربة استخدام سلسة وتفاعلية تتضمن:
- إدارة الكورسات والمسارات التعليمية والدروس.
- البث المباشر (Live Sessions) والدروس المسجلة بدقة عالية عبر HLS.
- نظام التقييمات والاختبارات التفاعلية (Assessments).
- إدارة اشتراكات الطلاب والشؤون المالية (Finance & Enrollments).
- لوحات تحكم متقدمة للتحليلات (Analytics & Dashboards).
- دعم متعدد اللغات (العربية والإسبانية/الإنجليزية RTL & LTR).

## 🚀 لماذا هذا الستاك؟ المميزات والرؤية الاستراتيجية

تم اختيار هذا الستاك بناءً على دراسة استراتيجية مقارنة بين الحلول المتاحة، مع إعطاء الأولوية لكل من: **الأداء، الأمان، سهولة الصيانة، والتوسع المستقبلي (Scalability & Maintainability)**.

### 1. التكامل الكامل في الأنماط (Contract-Driven Architecture & End-to-End Type Safety)
- **الميزة**: باستخدام `drf-spectacular` في الـ Backend و `openapi-typescript` في الـ Frontend، يتم توليد أنواع TypeScript تلقائياً من الـ API Endpoints.
- **الفائدة**: إلغاء الأخطاء الناتجة عن عدم تطابق البيانات بين الواجهة الأمامية والخلفية كلياً (Zero Mismatch Errors)، وسرعة عالية جداً في التطوير بدون الحاجة لكتابة Types يدوياً.

### 2. التوافق التلقائي للبيانات (Snake_case ⚡ CamelCase Isolation)
- **الميزة**: يعالج الـ Backend البيانات بصيغة `snake_case` القياسية في Python، بينما يتم تحويل الـ JSON تلقائياً بواسطة `djangorestframework-camel-case` ليتطابق مع الـ Frontend الذي يعمل بـ `camelCase`.
- **الفائدة**: المحافظة على النظافة والمعايير القياسية لكلا العالمين دون الحاجة لكتابة أدوات تحويل يدوية.

### 3. أداء فائق في الواجهة الأمامية (Vite + React Query + Framer Motion)
- **الميزة**: 
  - **Vite + SWC** يمنح سرعة تجميع وبناء غير مسبوقة مقارنة بـ Webpack Traditional.
  - **TanStack React Query** يعالج مشاكل الـ Server State مثل Caching, Deduplication of Requests, و Automatic Background Refetching، مما يلغي الحاجة لـ Redux المعقدة للبيانات القادمة من API.
- **الفائدة**: سرعة استجابة سريعة جداً للمستخدم (Lightning fast UX) واستهلاك خفيف للذاكرة.

### 4. حماية وتأمين بدرجة مؤسسية (Enterprise Security & Isolation)
- **الميزة**: 
  - اعتماد **DRF SimpleJWT** مع تقنية **Token Rotation** و **Blacklisting** لحماية الجلسات ومنع تزوير الطلبات.
  - استخدام **Throttle Rates** مخصصة لحماية واجهات تسجيل الدخول والعمليات الحساسة من هجمات Brute Force.
  - وجود سكريبتات فحص أمني دائم (`Bandit` و `pip-audit` و `axe-core`).
- **الفائدة**: حماية منصة EduSmart من الثغرات الأمنية الشهيرة (OWASP Top 10) وضمان سلامة بيانات الطلاب والأكاديميات.

### 5. دعم البث المرئي والمحتوى التعليمي (HLS Video Streaming & Real-Time Ready)
- **الميزة**: استخدام **hls.js** يتيح تشغيل فيديوهات الكورسات والبث المباشر بتكيف تلقائي مع سرعة إنترنت الطالب (Adaptive Bitrate Streaming).
- **الفائدة**: منع التقطيع وتوفير تجربة مشاهدة ممتازة حتى مع الاتصالات الضعيفة.

### 6. بيئة اختبارات وجودة شاملة (Automated Quality Gates)
- **الميزة**: المنصة محمية بواسطة اختبارات شمولية في الـ Frontend (Vitest, Playwright) والـ Backend (Pytest, Ruff, Mypy, SonarQube).
- **الفائدة**: ثبات الكود (Stability) وعدم حدوث تراجعات (Regression) عند إضافة ميزات جديدة، وتسهيل عمل الفرق البرمجية الكبيرة (Teamwork Efficiency).

## ✨ الميزات الأساسية وسيناريوهات العمل (Core Features & Workflows)

تتميز منصة **EduSmart (أكاديمية كورسات)** بأربع ميزات تقنية أساسية تم بناؤها بمعمارية مؤسسية قوية تضمن تجربة مستخدم سلسة وأماناً فائقاً للبيانات:

---

### 1. خط أنابيب رفع ومعالجة الفيديو المتكيف (Chunked Video Upload & FFmpeg HLS Pipeline)

نظام متكامل لرفع ومعالجة مقاطع الفيديو التعليمية وتوفير بث فائق الأمان ومحمي ضد التسريب والسرقة:

#### ⚙️ المواصفات الهندسية:
* **الرفع المجزأ (Resumable 5MB Chunking)**: تقسيم الفيديو على المتصفح إلى أجزاء بحجم 5 ميجابايت لضمان ثبات الرفع حتى مع انقطاع أو بطء الاتصال، مع دعم ملفات حتى 1,024 ميجابايت (1 جيجابايت).
* **المعالجة الآلية عبر Celery + FFmpeg**: تشغيل مهمة غير متزامنة (`transcode_video_to_hls_task`) تقوم بتحويل الفيديو الأصلي إلى 3 جودات تكيفية (`720p`, `480p`, `360p`) بأجزاء مدتها 4 ثوانٍ (`hls_time 4`) وتوليد الـ `master.m3u8`.
* **التنظيف الذاتي للقرص**: حذف الملف الخام الأصلي من مجلد الـ Scratch فور نجاح المعالجة لتحرير المساحة التخزينية.
* **حماية البث بتوكنات Nginx `secure_link`**: تشفير روابط البث برمز MD5 هاش يربط الرابط بعنوان IP الخاص بالطالب مع مهلة صلاحية محددة بـ ساعتين فقط (7200 ثانية).
* **التجديد التلقائي للتوكن (Seamless Token Renewal)**: في حال انتهاء صلاحية الرابط أثناء المشاهدة أو حدوث خطأ 403، يقوم المشغل بتجديد الرابط تلقائياً دون مقاطعة الطالب.
* **العلامة المائية المتحركة الديناميكية**: إظهار معرف الطالب وبريده الإلكتروني على الشاشة بشكل متحرك لمنع تصوير الشاشة.

#### 🔄 مخطط مسار العمل (Workflow):
```
[متصفح المحاضر] 
   │ 1. اختيار ملف الفيديو والتحقق من الحجم والصيغة
   │ 2. تجزئة الملف إلى قطع 5MB وإرسالها متتالية (/videos/upload-chunk/)
   ▼
[Django Backend API] 
   │ 3. استقبال القطع وحفظها في مجلد معزول (media/scratch/raw_videos/{upload_id}/)
   │ 4. طلب اكتمال الرفع (/videos/upload-complete/) وتجميع القطع في ملف خام
   │ 5. إنشاء سجل Video بحالة 'pending' وإطلاق مهمة Celery غير متزامنة
   ▼
[Celery Worker + FFmpeg] 
   │ 6. استخراج مدة الفيديو وتحويله إلى جودات (720p / 480p / 360p) بصيغة HLS
   │ 7. توليد master.m3u8 وحذف الملف الخام الأصلي وتحديث حالة الفيديو إلى 'ready'
   ▼
[متصفح الطالب (SecureVideoPlayer)] 
   │ 8. طلب رابط البث المشفر (/lessons/{id}/signed-stream-url/)
   │ 9. توليد Nginx secure_link مقيد بـ IP الطالب وصالح لساعتين
   │ 10. تشغيل الفيديو عبر hls.js مع التجديد التلقائي عند انتهاء الصلاحية
```

#### 📌 السيناريوهات المحتملة (Possible Scenarios & Edge Cases):
1. **سيناريو الرفع عبر اتصال ضعيف أو متقطع**:
   - *ما يحدث*: يتم رفع الفيديو مجزأً؛ في حال فشل رفع أحد الأجزاء (Chunk)، تتم إعادة محاولة رفعه تلقائياً دون إعادة رفع الأجزاء السابقة.
2. **سيناريو رفع ملف بصيغة غير مدعومة أو بحجم أكبر من 1GB**:
   - *ما يحدث*: يعترض المتصفح الملف فورياً ويظهر تنبيهاً بالحدود المسموح بها، مع حماية إضافية على مستوى السيرفر ترفض الملف بـ `400 Bad Request`.
3. **سيناريو انتهاء صلاحية رابط البث أثناء مشاهدة الدرس**:
   - *ما يحدث*: عند طلب جزء فيديو جديد بعد انقضاء الساعتين، يرجع الخادم `403 Forbidden`؛ يلتقط مشغل `hls.js` الخطأ فوراً ويستدعي دالة `onTokenExpired` لطلب توكن جديد واستئناف التشغيل بسلاسة تامة.
4. **سيناريو محاولة تشغيل الفيديو من جهاز أو IP مختلف عن الطالب المصرح له**:
   - *ما يحدث*: يرفض خادم Nginx أو المشغل طلب البث مباشرة بسبب عدم تطابق الـ IP المربوط بالـ Hash Token.

### 2. منشئ ومحرر الدورات التفاعلي (Interactive Course Builder)

أداة شاملة ومرنة تتيح للمحاضر والمشرف بناء المنهج الدراسي وإدارته باحترافية وسرعة:

#### ⚙️ المواصفات الهندسية:
* **إدارة بيانات الدورة (Course Metadata)**: ضبط العنوان، التصنيف، الوصف، التسعير، دعم الدورات المجانية، والتبديل المباشر بين حالة المسودة (Draft) والمنشور (Published).
* **إعادة الترتيب الحركي السلس (Framer Motion Reordering)**: إمكانية تحريك وترتيب الوحدات والدروس تصاعدياً وتنازلياً مع تحديث الترتيب (`order`) فورياً في قاعدة البيانات.
* **إدارة الوحدات والدروس (Modules & Lessons CRUD)**: إضافة وتعديل وحذف الوحدات والدروس وتحديد نوع الدرس (فيديو، مقال نصي، اختبار، واجب) ومدته التقديرية.
* **ربط الفيديو المباشر من المكتبة**: نافذة لاختيار فيديو تمت معالجته مسبقاً، أو رفع ومعالجة فيديو جديد مباشرة من داخل نفس الشاشة.
* **المعاينة الفورية للطلاب (Live Preview Mode)**: إتاحة زر للانتقال الفوري إلى صفحة الدورة واستعراض تجربة الطالب كما ستظهر له.

#### 🔄 مخطط مسار العمل (Workflow):
```
[منشئ الدورات (InstructorCourseBuilder)]
   │ 
   ├──► 1. تعبئة تفاصيل الدورة (العنوان، السعر، التصنيف، الوصف) ──► حفظ فوري
   │ 
   ├──► 2. إضافة وحدة دراسية (Module) ──► إعادة ترتيب الوحدات بأزرار تحريك سلسة
   │ 
   ├──► 3. إضافة درس (Lesson) وتحديد نوعه ومدته وخيار المعاينة المجانية
   │ 
   ├──► 4. فتح نافذة الفيديو ──► رفع فيديو جديد (Chunked) أو اختيار فيديو جاهز
   │ 
   ├──► 5. فتح محرر الملخص ──► كتابة نقاط الدرس وإرفاق ملف PDF للتحميل
   │ 
   └──► 6. تفعيل حالة "منشور (Published)" ──► إتاحة الدورة للطلاب فورياً
```

#### 📌 السيناريوهات المحتملة:
1. **سيناريو إنشاء وتجهيز دورة جديدة كمسودة (Draft)**:
   - *ما يحدث*: يقوم المحاضر بإنشاء الدورة كمسودة؛ تظل الدورة محجوبة عن كتالوج الطلاب العام إلى حين اكتمال رفع الفيديوهات، ثم يقوم بنشرها بنقرة زر واحدة.
2. **سيناريو إعادة ترتيب المنهج الدراسي**:
   - *ما يحدث*: عند تحريك وحدة أو درس للأعلى أو للأسفل، يتم إرسال طلب `PATCH` متزامن لتحديث قيم الـ `order` لكل من العنصرين المتبادلين، وتحدث الواجهة فورياً بدون إعادة تحميل الصفحة.
3. **سيناريو حذف وحدة دراسية تحتوي على دروس**:
   - *ما يحدث*: تطلب الواجهة تأكيد الحذف وتطبق الحذف المتتالي (Cascade Delete) على مستوى السيرفر مع إعادة ترتيب باقي الوحدات.

### 3. ملخصات الدروس ومرفقات PDF (Lesson Summaries & Downloadable Resources)

ميزة تعليمية تتيح تزويد الدروس بشروح مكتوبة وملفات مساعدة تلخص أهم القوانين والمفاهيم:

#### ⚙️ المواصفات الهندسية:
* **ربط أحادي بين الدرس وملخصه (`OneToOneField`)**: نموذج `LessonSummary` مستقل ومرتبط بنموذج `Lesson`.
* **دعم المرفقات (PDF Attachment)**: إمكانية إرفاق ملف PDF مع الملخص النصي وحفظ اسم الملف الأصلي ورابط التنزيل المباشر.
* **صلاحيات وصول مقيدة (Role-Based Access Control)**: قراءة الملخص متاحة فقط للطلاب المشتركين بالدورة والمالك والإدارة، بينما التعديل محصور بمالك الدورة والإدارة فقط.
* **تبويب مخصص وسهل الوصول في مشغل الدرس**: تبويب "ملخص الدرس" بجوار مشغل الفيديو في صفحة `LessonDetail.tsx`.

#### 🔄 مخطط مسار العمل (Workflow):
```
[المحاضر في منشئ الدورات]
   │ 1. كتابة الملخص النصي واختيار ملف الـ PDF المرفق
   │ 2. حفظ الملخص (POST /summaries/ عبر FormData)
   ▼
[سيرفر المنصة]
   │ 3. حفظ النص والملف في مسار آمن والتحقق من ملكية المحاضر للدورة
   ▼
[صفحة الدرس للطالب (LessonDetail)]
   │ 4. استرجاع بيانات الملخص عبر API
   │ 5. عرض الشرح النصي المنسق وزر "تحميل PDF" التفاعلي
```

#### 📌 السيناريوهات المحتملة:
1. **سيناريو طالب مسجل يستعرض الشرح وينزل الملخص**:
   - *ما يحدث*: يظهر تبويب "ملخص الدرس" للطالب تلقائياً، ويستطيع قراءة الشرح وتحميل ملف الـ PDF للطباعة بنقرة زر واحدة.
2. **سيناريو محاولة مستخدم غير مشترك الوصول لملخص مدفوع**:
   - *ما يحدث*: يتم رفض الطلب فورياً عبر بوابة الصلاحيات (`IsLessonCourseOwnerOrAdmin`) ويمنع الوصول لمحتوى الملخص ومرفقه بـ `403 Forbidden`.
3. **سيناريو تعديل الملخص واستبدال ملف الـ PDF**:
   - *ما يحدث*: يستطيع المحاضر تعديل الشرح أو رفع ملف PDF جديد في أي وقت، وتقوم واجهة الطالب بتحديث المحتوى تلقائياً عبر TanStack Query Cache Invalidation.

### 4. محرك الامتحانات والتصحيح الآلي (Exam Engine & Auto-Grading)

نظام تقييم واختبارات متطور يدعم التقييم الفوري ومراقبة النزاهة:

#### ⚙️ المواصفات الهندسية:
* **دعم 5 أنواع من الأسئلة**:
  1. *اختيار من متعدد (Multiple Choice)*.
  2. *صواب أو خطأ (True / False)* (يدعم الصيغ العربية والإنجليزية: صواب/خطأ، True/False).
  3. *إكمال الفراغ (Fill in the Blank)* (يدعم قائمة الإجابات المرادفة المقبولة).
  4. *التوصيل (Matching)* (حساب نسبي دقيق لدرجات الأزواج الصحيحة).
  5. *السؤال المقالي (Essay)* (تترك الدرجة مؤقتة للتصحيح اليدوي بواسطة المعلم).
* **التصحيح التلقائي الآمن على الخادم (Server-side Evaluation)**: يتم تقييم الإجابات ومقارنتها بمفتاح الإجابة السري على الخادم حصرياً لمنع أي تلاعب من المتصفح.
* **حد النجاح القابل للتخصيص (`pass_threshold`)**: تحديد نسبة مئوية مطلوبة لاجتياز الامتحان (مثلاً: 60% أو 50%) واحتساب حقل `is_passed` تلقائياً.
* **مراقبة النزاهة وتبديل النوافذ (Tab Switching Detection)**: رصد عدد مرات خروج الطالب من نافذة الامتحان وتسجيلها في محاولة الامتحان (`tab_switches_count`).
* **شاشة النتائج الفورية التفاعلية (`ExamResult.tsx`)**:
  - عرض الدرجة الإجمالية والنسبة المئوية ومقارنتها بحد النجاح.
  - إطلاق احتفال بصري بـ Confetti للطلاب الناجحين لتعزيز التحفيز.
  - إظهار تفاصيل المحاولة والمدة المستغرقة وملاحظات المعلم إن وجدت.
  - زر مباشر لإعادة المحاولة (في حال سماح الامتحان بمحاولات إضافية).
* **لوحة استعراض المحاولات للمحاضر (`/exams/{id}/attempts/`)**: تتيح للمعلم تتبع نتائج جميع الطلاب ومستوى درجاتهم وحالات نجاحهم.

#### 🔄 مخطط مسار العمل (Workflow):
```
[بدء الامتحان (POST /exams/{id}/start/)]
   │ 1. التحقق من صلاحية الطالب، حالة نشر الامتحان، ومواعيد البداية والنهاية
   │ 2. التحقق من عدد المحاولات السابقة مقارنة بـ attempts_allowed
   │ 3. إنشاء سجل StudentExam بحالة IN_PROGRESS وتحديد وقت البدء
   ▼
[جلسة حل الامتحان للطالب]
   │ 4. عداد زمني للوقت المتبقي ورصد تبديل النوافذ (Tab Switches)
   │ 5. إرسال الإجابات (POST /exams/{id}/submit/)
   ▼
[التصحيح الخادمي الحصري (Server-side Grading)]
   │ 6. التحقق من عدم تجاوز مهلة الامتحان (Duration + 2 min Grace Period)
   │ 7. تصحيح الأسئلة الموضوعية واحتساب الدرجة الكلية total_score
   │ 8. مقارنة النسبة المئوية بـ pass_threshold وتحديد is_passed
   │ 9. إذا احتوى الامتحان على أسئلة مقالية: تظل الحالة SUBMITTED بانتظار المعلم
   │    إذا كانت جميع الأسئلة موضوعية: تتحول الحالة فوراً إلى GRADED
   │ 10. إرسال تنبيه فوري لولي الأمر عبر تلجرام (Telegram Alert Task)
   ▼
[شاشة النتائج الفورية (ExamResult.tsx)]
   │ 11. عرض شارة النجاح/الرسوب ومخطط النسبة المئوية واحتفال Confetti
   │ 12. خيارات المتابعة: إعادة المحاولة أو العودة للمسار التعليمي
```

#### 📌 السيناريوهات المحتملة:
1. **سيناريو اجتياز الطالب للاختبار الموضوعي فورياً**:
   - *ما يحدث*: يرسل الطالب إجاباته، يحسب السيرفر الدرجة بدقة (مثلاً: 85/100)، ويتحقق من تجاوز حد النجاح (60%)؛ يتم توجيهه لشاشة النتائج مع احتفال الـ Confetti وإرسال إشعار فوري لولي أمره بنتيجته.
2. **سيناريو عدم اجتياز الطالب للاختبار**:
   - *ما يحدث*: يحصل الطالب على نسبة أقل من حد النجاح؛ تظهر له شاشة النتيجة توضح مواضع الضعف مع زر "إعادة المحاولة" إذا كانت هناك محاولات متبقية.
3. **سيناريو امتحان يحتوي على سؤال مقالي (Essay Question)**:
   - *ما يحدث*: يتم تصحيح الأسئلة الموضوعية آلياً، ويوضع الامتحان بحالة `SUBMITTED` مع رسالة توضح أن النتيجة النهائية ستظهر بعد تصحيح المعلم للسؤال المقالي عبر نقطة `grade-essay`.
4. **سيناريو استنفاد الطالب لجميع محاولاته المتاحة**:
   - *ما يحدث*: عند محاولة بدء الامتحان مرة أخرى بعد استنفاد المحاولات (مثلاً: 2 من 2)، يرفض السيرفر الطلب مع رسالة تفيد باستنفاد كافة المحاولات المصرح بها.
5. **سيناريو خروج الطالب المتكرر من شاشة الاختبار (الغش المحتمل)**:
   - *ما يحدث*: يرصد النظام كل عملية تبديل نافذة أو تصغير للمتصفح ويسجلها في `tab_switches_count` لتمكين المحاضر من مراجعتها في لوحة تحليلات الامتحان.

## 🏁 دليل التشغيل السريع (Quick Start Guide)

### 🚀 1. التشغيل التلقائي الفوري بنقرة واحدة (One-Click Launch for Demo):
للبدء الفوري وعرض المنصة محلياً بكامل كفاءتها:
- اضغط مرتين (Double Click) على الملف [`start_edusmart.bat`](file:///f:/FlashCard/edusmart/start_edusmart.bat).
- سيقوم السكريبت تلقائياً بـ:
  1. التأكد من تشغيل خدمة PostgreSQL (`postgresql-x64-18`).
  2. تفعيل البيئة الافتراضية للـ Backend وتطبيق الهجرات `migrate`.
  3. تشغيل Django Backend Server على `http://127.0.0.1:8000/`.
  4. تشغيل React/Vite Frontend Server على `http://localhost:8080/`.
  5. فتح المتصفح التلقائي على رابط المنصة.

### 🛑 2. إيقاف المنصة وإعادة النظام لحالته الطبيعية (Shutdown & Restoration):
عند الانتهاء من العرض وتريد إغلاق الخوادم كلياً:
- اضغط مرتين (Double Click) على الملف [`stop_edusmart.bat`](file:///f:/FlashCard/edusmart/stop_edusmart.bat).
- سيقوم السكريبت بإغلاق سيرفرات الباك إند والفرونت إند فوراً وتحرير المنافذ (8000 و 8080) كلياً.
